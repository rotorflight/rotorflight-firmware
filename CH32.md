# Using Rotorflight on CH32 flight controllers

This guide covers building the CH32H417 firmware in this repository and programming it onto a compatible flight controller. CH32 support is a port and currently has a target for the CH32H417. Having a CH32 MCU alone does not make a flight controller compatible: the firmware target must also match the board's pinout, sensors, USB wiring, and other hardware.

> **Bench safety:** Remove the main and tail rotor blades before connecting power or configuring the flight controller. Use firmware built for the exact board revision, and keep a backup of the existing configuration before erasing or replacing firmware.

## Requirements

- A clone of this Rotorflight firmware repository.
- Git Bash (MinGW64) and GNU Make on Windows, or the build tools required by the repository on Linux/macOS.
- Internet access the first time you install the CH32 compiler.
- A supported CH32 flight controller with a matching Rotorflight target. The example target below is `CH32H417`.
- A compatible WCH programming probe and the programming connections documented for your flight controller. For the programming steps below, use WCH-LinkUtility with a compatible WCH-Link probe.

MounRiver Studio is not required to compile the firmware. Make can use the repository-local WCH RISC-V compiler. For detailed toolchain selection and troubleshooting, see [Building CH32 on Windows](docs/development/Building%20CH32%20on%20Windows.md).

## Install the compiler

Open Git Bash in the repository root and install the WCH RISC-V toolchain:

```bash
make ch32_sdk_install
```

This downloads and extracts the compiler into `tools/riscv-wch-elf-12.2.0/`. It is a local build dependency and does not need MounRiver Studio.

Check that Make selects the local compiler:

```bash
make -pn TARGET=CH32H417 | grep -E '^(CH32_SDK_PREFIX|CH32_SDK_CC|CROSS_CC)[[:space:]]*[:?+]?='
```

The compiler paths should start with `./tools/riscv-wch-elf-12.2.0/bin/`.

## Build the firmware

Build the CH32H417 target from the repository root:

```bash
make TARGET=CH32H417
```

To remove previous CH32H417 build output first:

```bash
make clean TARGET=CH32H417
make TARGET=CH32H417
```

The Intel HEX image is written to `obj/rotorflight_<version>_CH32H417.hex` (for example, `obj/rotorflight_4.6.0_CH32H417.hex`). The ELF file is written to `obj/main/rotorflight_CH32H417.elf`.

Always pass `TARGET=CH32H417` for this board. Without a target argument, Make defaults to `STM32F7X2`.

## Program the flight controller

The generic Makefile flash targets in this repository are configured for STM32 serial/DFU flashing. They do not configure a CH32H417 programmer, so do not assume `make CH32H417_flash` or `make dfu_flash TARGET=CH32H417` is the right CH32 programming method.

Use a compatible WCH programming probe and WCH-LinkUtility, following the flight controller manufacturer's instructions for the correct connector, wiring, chip selection, and boot mode:

1. Save the existing flight-controller configuration with Rotorflight Configurator if you need to preserve it.
2. Disconnect flight-controller power and connect the WCH-Link probe to the board's documented programming interface. Do not guess the pinout or voltage from another board.
3. Power the board as specified by its manufacturer and open WCH-LinkUtility.
4. Select the RISC-V core and CH32H41x series, then identify the actual MCU on the board.
5. Select the generated `obj/rotorflight_<version>_CH32H417.hex` file.
6. Program and verify the image, then reset/run the MCU. Only erase the full chip if the board's instructions say that is appropriate; full erase can remove other contents such as an existing bootloader or saved data.
7. Disconnect the programmer, connect the FC over USB, and use a Rotorflight Configurator version that supports this firmware build to connect and configure it.

WCH-LinkUtility and its supported-device list are available from [WCH's downloads page](https://www.wch-ic.com/downloads). The exact programmer, wiring, and boot procedure depend on the FC design. WCH also documents programming the CH32H417 using WCH-LinkUtility in its [CH32H417 evaluation board reference](https://www.wch-ic.com/downloads/CH32H417EVT_ZIP.html); follow your FC manufacturer's documentation where its design differs.

## Board support and troubleshooting

- `CH32H417` is a board/firmware target, not a universal target for every CH32-based FC. A different board needs its own target configuration and a compatible MCU port.
- If the generated HEX does not connect in Configurator after programming, check that the image matches the FC board revision and that USB, clock, and peripheral pin definitions match the board.
- If Make reports that the CH32 compiler is missing, run `make ch32_sdk_install` and confirm the compiler path with the command in [Install the compiler](#install-the-compiler).
- If the Make output shows a MounRiver path, distinguish the `make` executable from `riscv-wch-elf-gcc`: Make itself can come from MounRiver while the compiler still comes from `tools/riscv-wch-elf-12.2.0/bin/`.
